# 调度系统

## 目标

群聊调度要解决三个问题：

```text
谁适合说
谁值得补充
什么时候结束
```

不是固定顺序，也不是全员轮流。

## 决策流程

```text
用户消息
  ↓
解析 @
  ↓
解析自然点名
  ↓
识别硬性单人指令
  ↓
本地粗筛候选
  ↓
批量评估
  ↓
计算综合分
  ↓
确定发言顺序
  ↓
流式生成
  ↓
补充评估
  ↓
结束
```

## 优先级

```text
硬点名 > @ > 软点名 > 普通调度
```

### 硬点名

用户明确表达“只要这个人”或“其他人不要说话”：

```text
只有小猫说
小猫，其他人闭嘴
就咱俩说话
```

命中后本轮只允许被点名者发言。

### 软点名

用户叫了某个角色，但没有排他：

```text
小猫，你说说
```

被点名者优先，其他人达到门槛仍可补充。

### 普通提及

```text
小猫昨天说想去公园
```

只提高意愿分，不强制第一。

## 候选粗筛

不会把全群角色都送进模型，而是先本地筛选：

- 被 @ 的角色
- 自然点名角色
- 最近没说话的角色
- 与当前消息关键词重合的角色
- 发言次数较少的角色

通常保留 top5 进入评估。

## 评估输出

```json
{
  "member_id": 27,
  "relevance": 4,
  "novelty": 3,
  "willingness": 5,
  "can_answer": true,
  "would_repeat": false
}
```

## 综合分

```text
首位发言：
FIRST = relevance × 0.5 + novelty × 0.3 + willingness × 0.2

后续补充：
FOLLOW = novelty × 0.5 + relevance × 0.3 + willingness × 0.2
```

附加规则：

- 等待越久，意愿加成越高
- 最近发言越多，频率惩罚越高
- 未达到最低分不发言

## 人数控制

`max_turns` 是安全上限，不是目标人数：

```text
普通消息：最多 5 人
复杂讨论：最多 7 人
开放讨论：最多 10 人
```

实际可能只有 1 人回复。

## 去重与重复

- 第一遍每人最多一次
- 第二遍只允许高价值重复
- 低新颖度、低综合分不重复
- 同一角色本轮重复最多一次

## 失败处理

```text
评估超时
  → 读取本群最近一次成功缓存
  → 没有缓存则使用本地分兜底

单个角色生成失败
  → 跳过该角色
  → 不终止整轮

连续失败
  → 达到阈值才结束本轮
```

## 本地分

本地分只在以下场景使用：

- 粗筛排序
- 同分排序
- 评估失败兜底

不直接加进模型综合分，避免量纲压过模型判断。

## 设计原则

```text
稳定优先于吞吐
完成率优先于速度
可解释优先于“更聪明”
```
